# 中国专利通俗解读

## 任务边界

本 Skill 只帮助读懂已经存在的专利文献，不起草当前申请，也不把通俗解释写成侵权、无效、新颖性或创造性法律意见。

优先使用用户提供的全文或 PDF。只有公开号时，从可核验的官方或稳定著录页取得文本，并记录本次证据范围是全文、摘要还是部分文本。只有摘要时，不推断全部权利要求、实施方式或法律范围。

## 工作流程

1. 核对公开号、标题、申请人、公开日、文本版本和来源链接。
2. 提取独立权利要求、从属权利要求及说明书关键段落。
3. 人工核对父子关系，特别是“权利要求 1 或 2”“权利要求 1 至 3”等多项引用。
4. 为每项从属权利要求说明它相对父项新增的限定，不重复套话。
5. 用通俗故事线解释技术问题、核心思路、实施步骤、关键对象、技术效果和背景差别。
6. 建立“技术特征—权利要求—说明书段落—附图”对照。
7. 把额外检索线索单列为候选或推测，不混入专利原文证据。

## 默认交付

- 简洁 Markdown 解读；
- 权利要求树；
- 关键术语表；
- 特征与证据定位表；
- 必要的附图引用；
- 证据范围、版本和不确定项。

用户明确需要时，可增加 Obsidian 笔记、Canvas 或术语双链；没有 Obsidian 也应完成标准 Markdown 解读。

## 禁止事项

- 不把检索线索或通俗改写冒充权利要求原文。
- 不根据摘要推断未公开或未读取的内容。
- 不把参考专利的技术、身份或附图带入另一件申请。
- 不在用户可见标题中保留脚本名、字段路径或内部流水线痕迹。
- 不强迫用户安装笔记软件、主题或插件后才开始解读。
