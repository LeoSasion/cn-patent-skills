# 中国发明专利申请准备

先确认发明主题、已有材料、交付范围、模板和保密要求。只询问会实质影响交付的缺项，其他合理假设随稿说明。

## 规范优先级

- 在评估、撰写和申请文件转换前，按 [官方规范核验](references/filing-boundary.md) 核对适用的现行法律、审查指南和 CNIPA 要求。同一案件已核验且范围未变时可复用记录。
- 用户提供的机构或个人模板控制交底书字段和版式。默认交底书采用 `yjmm10/patent-skills` 的六章模板、时间戳命名和 A4 Word，完整申请采用 `HuangXinzhe/cn-patent-drafting` 的分件交付。在两份上游均有规定的地方，按 [交底书与申请文件](references/document-contracts.md) 执行。
- 申请正文以已确认的技术事实为依据。区分原始证据、技术推断和待发明人确认事项。未确认的身份、优先权、在先申请和官方编号在确认表单独标记。

## 按任务执行

- **创意评估或论文转专利**：从论文、设计、实验、代码或已有材料提取技术问题、手段、效果和可实施依据。主题未确定时列 3–5 个有依据的候选点（不足则按实际列出），给出可能的权利要求客体、材料缺口和主要风险。默认深挖最强的一项。对评估结论区分已支持、风险与信息不足。
- **取证和查新**：先读 [事实账本](references/evidence-gate.md) 和 [查新与权利要求](references/search-and-claims.md)。交底书定稿、查新评估、主权项或全套材料涉及现有技术时，先核验公开文献和适用日期。按用户明确要求可先出未查新草稿，并记录证据范围与待核对项。
- **技术交底书**：读 [交底书与申请文件](references/document-contracts.md)，按用户模板或 [默认六章模板](assets/default-disclosure-template.md) 起草。定稿交付同名的 Markdown 与 A4 DOCX。只请求交底书时，交付到该阶段。
- **权利要求、说明书、摘要或完整申请**：读 [交底书与申请文件](references/document-contracts.md) 和 [查新与权利要求](references/search-and-claims.md)。先确定主要权利要求及证据支持，再完成对应说明书、摘要和附图。完整申请交付分件 Markdown 与 DOCX，含初步查新笔记、请求书信息确认表及提交文件清单。PDF 用于用户要求的审阅副本。绘图和文档质检见 [附图与验证](references/figures-and-validation.md)。
- **既有稿修订**：定位用户指定基准，区分合并、纠错、保护范围调整或重写。保留未受影响的章节，复查联动术语、公式、附图和权项，新建时间戳版本并记简短的修订摘要。改变核心特征时复核检索与支持关系。命名、留痕和验收见 [交付与版本](references/delivery-contract.md)。
- **电子提交准备**：读 [官方规范核验](references/filing-boundary.md)，整理待转换文本、文件类别和身份缺口。XML 的可提交状态以当期官方规范、工具及真实系统校验为依据。

代码案件确认仓库、分支、提交和工作树，若存在项目索引则先用 CodeGraph。论文、实验或非软件发明按各自原始材料取证。仅使用可公开的术语在线检索，内部身份、客户数据、未公开材料及证据保存在受控位置。

专利申请草稿保持正文干净，技术证据表、查新过程、修订记录与待确认事项另列。本 Skill 协助准备材料，正式提交、权属和保护范围判断由用户与具备相应资质的专业人员确认。已有公开专利的阅读理解使用 `$explain-cn-patent`。
