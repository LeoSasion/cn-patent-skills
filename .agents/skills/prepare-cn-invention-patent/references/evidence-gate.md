# 代码事实与验证门禁

## 来源优先级

按以下顺序确定技术事实：

1. 用户本轮明确确认的目标和事实；
2. 当前工作空间中的代码、模式、迁移、配置和机器合同；
3. 绑定当前版本实际执行的测试及回执；
4. 当前设计文档；
5. 当前案件已经核验的规范申请源；
6. 旧交底书、旧申请稿和会议记录，仅作为定位线索；
7. 参考专利、论文和开源项目，仅用于现有技术或写法比较。

旧稿与当前实现冲突时，以当前实现为准。用户明确要求不参考旧稿时，不读取旧稿来选择术语、流程或保护点。

## 仓库核验

修改文件、运行测试或形成事实结论前：

- 核对仓库根目录、分支、`origin` 和当前提交标识；
- 确认没有跨入同名或不同后缀的其它项目；
- 仓库存在 `.codegraph/` 时先用 CodeGraph 获取符号源码和调用路径；
- 记录工作树是否包含未提交修改，不把 `HEAD` 单独称为完整代码基线；
- 不为方便取证启动会改写其他项目缓存、数据库或运行状态的命令。

## 事实账本

为每项拟写技术特征记录：

| 字段 | 要求 |
|---|---|
| 统一中文名称 | 一个对象只用一个主称谓 |
| 技术关系 | 输入、输出、状态、执行顺序、约束和异常路径 |
| 实现证据 | 文件、符号、调用路径或机器合同 |
| 验证证据 | 测试名、运行命令、结果、时间和当前版本 |
| 证据性质 | 生产事实、模拟验证、静态检查或文档声明 |
| 状态 | 已实现、部分实现、未实现、无法确认 |
| 写作层级 | 独立权项、从属权项、实施例或不得写入 |
| 限制 | 尚未覆盖的边界和失败条件 |

每个核心关系必须同时有实现证据和可重复验证。函数名、接口、注释、占位实现和测试名称本身不是能力事实。

## 模拟数据

- 明确写成“模拟数据验证”或“测试夹具验证”。
- 只证明该输入下的逻辑行为，不推导真实客户效果、吞吐量、长期稳定性或生产数据结论。
- 经营数字、排名和趋势必须绑定真实工作空间和真实数据源的已执行证据。
- 未覆盖真实多机、网络分区、硬件断电、并发冲突或长期性能时，逐项列为未验证。

## 核心能力门禁

下列能力不能仅凭正常路径模拟测试进入独立权利要求：

- 持久化或事务原子性；
- 中断恢复、幂等或崩溃一致性；
- 跨节点、跨进程或分布式一致性；
- 安全、隔离和权限保证；
- 性能、精度、吞吐量或可用性指标。

针对拟保护的异常机制，至少运行与主张相称的负向、边界和恢复测试。无法验证时，降低写作层级或删除该主张。

## 代码改造分流

只有用户已要求实现或优化代码时才进入改造：

1. 说明缺口及其对创新链的影响；
2. 在当前项目内实现，不跨仓库复制未授权代码；
3. 补正向、负向、版本漂移和恢复测试；
4. 重新生成事实账本；
5. 以当前提交标识、工作树状态和关键文件 SHA-256 冻结新基线。

用户只要求审查、分析或写文档时，不修改代码来倒推支持既定文案。

## 事实审计输出

至少交付：

- 能力事实表；
- 核心调用链；
- 已运行测试及结果；
- 模拟与生产边界；
- 未实现或未验证缺口；
- 可进入不同权利要求层级的特征清单。

不要用“代码看起来支持”“理论上可以”替代证据。
