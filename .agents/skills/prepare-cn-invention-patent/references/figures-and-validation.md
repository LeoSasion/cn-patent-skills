# 附图、渲染与一致性验证

## 附图内容先于美化

先依据代码和事实账本建立步骤、状态和对象关系，再绘图。旧图和旧正文不能单独决定正确流程。

每幅图只承担一个清晰任务：

- 总体方法图：正常主流程；
- 系统模块图：模块及主要数据流；
- 对象关系图：快照、回执、运行对象、事务或状态之间的绑定；
- 异常或恢复图：条件入口、状态判断和停止分支。

正常路径和仅在异常时进入的恢复路径不要画成必然串行。

## 图面规则

- 使用黑、白、灰和清晰中文；不使用装饰色、阴影或手绘效果。
- 交付 PNG 和可编辑源文件，优先 Draw.io；Mermaid 可用于简单草图，但不是强制格式。
- 流程箭头方向统一；限制说明用注释框，不画成共同后续步骤。
- 禁止没有连接点或跨线桥的交叉线。
- 分支条件写在对应箭头或判断框附近。
- 模块编号 100、200、210 等仅表示附图标记；正文必须解释其含义，不把它们解释成流程顺序、端口号或代码行号。
- 图号、模块号、步骤号和对象名称与正文完全一致。
- Draw.io 与 PNG 的节点、边、方向和标签保持一致；不能只修导出图。

## 图文闭环

逐图检查：

1. 图中每个核心节点在正文中定义；
2. 正文每次“参见图 N”都对应真实附图；
3. 每幅图至少被正文明确引用一次；
4. 方法步骤、系统模块和权利要求关系一致；
5. 恢复分支覆盖代码中的全部状态，包括证据不完整和状态冲突；
6. 图中没有旧术语、未实现模块或不必要产品功能。

为 DOCX 内嵌图写有意义的替代文字。校验内嵌媒体 SHA-256 与外部最终 PNG 一致。

## DOCX 检查

使用 documents Skill：

- 盘点段落、表格、页眉、页脚和内容控件；
- 保持用户模板几何和样式；
- 图片使用行内布局，除非模板明确要求浮动；
- 检查批注、修订、作者、自定义属性和隐藏内容；
- 检查宏、嵌入对象、外部关系和可能触发联网更新的链接；
- 渲染每一页并按 100% 查看；
- 检查裁切、重叠、异常断词、孤立标题、空白异常页和表格越界。

结构审计不能替代视觉审计。无法实际渲染时，明确说“未完成视觉检查”，不要声称页面通过。

## PDF 检查

### 申请前校对版式

- A4 纵向，建议上边距 25 mm、左边距 25 mm、右边距 15 mm、下边距 15 mm。
- 全文黑白，无徽标、二维码、外框、官方印章或仿制授权公告样式。
- 封面依次显示“发明专利申请文件”“申请前校对稿（非电子提交格式）”、发明名称、已确认身份、摘要和摘要附图；未知身份直接省略。
- 权利要求书、说明书和说明书附图分别另起新页。
- 正文优先宋体，标题优先黑体；权利要求一项一段，说明书非标题段连续编号。
- 说明书附图保持规范顺序，图号和图形放在同页，不新增规范源没有的示意图。

使用 PDF Skill：

- 交叉核对页数；
- 渲染所有页面为图片；
- 检查 A4 页面、页眉、章节起始、权利要求编号、说明书段落号、图号和摘要；
- 检查字体、裁切、重叠、旋转、空白页、加密和异常附件；
- 逐项比较规范申请源与 PDF 中的题目、摘要、每项权利要求、说明书正文和附图数量；
- 校对封面必须出现“申请前校对稿（非电子提交格式）”。

不要用固定感知哈希或少量页面抽查替代全部页面检查。

## 交付审计

生成并核验：

- 来源及角色清单；
- 主要文件 SHA-256；
- DOCX 结构与嵌图检查；
- PDF 页面和内容检查；
- Draw.io XML 可解析检查；
- 原模板和旧版哈希不变；
- Git tracked、staged 和未忽略的保密文件计数符合要求。

允许保留原模板布局表格没有表头等非实质警告，但必须记录原因。任何高风险内容、图片或来源错误都要修正后再交付。
