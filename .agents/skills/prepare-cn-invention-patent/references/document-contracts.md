# 交底书与申请文件

交底书服务于技术交接。申请文件使用独立可编辑的 Markdown 源，Word 和可选 PDF 从这些源派生。技术事实由本案材料控制。参考专利用于查新或学习文体。

## 技术交底书

优先使用用户给出的模板。无模板时，使用 [默认六章交底书](../assets/default-disclosure-template.md)。同一案件的 MD 与 DOCX 保持章节和技术内容一致。

模板中的提示、占位和示例流程图用于起稿。定稿时替换成案件内容，确认缺项另记。已有交底书按用户选定的基准迭代，用户要求切换模板时再迁移章节。

1. 技术背景、现有技术和缺点。1.1 按技术方向归类，每件引用记录标识、公开源 URL、技术方案、适用场景及与本案相关的局限。认真阅读已核验的摘要和必要原文后用自己的话概括。1.2 写清具体缺点。
2. 待解决的技术问题。与第一章的缺点逐项对应。
3. 详细技术方案。给出 3.1 场景与约束、3.2 系统框图、3.3 模块关联、3.4 系统流程和按需的 3.4.1 符号与公式、3.5 关键技术参数。图示按技术方案选择。公式先引入，再列式并解释变量，参数表与公式符号保持一致。
4. 与现有技术相比的优点。交代技术手段如何产生效果，区分机理推断、实验或实际运行结果。
5. 技术关键点与欲保护点。聚焦解决问题的必要组合及可用于从属权项的特征。
6. 实施例、技术效果和相关申请。可替代方案放在与其技术逻辑相符的位置。相关申请未知时标记需确认。

对源稿中的公司名、客户名、项目代号、内部路径及可替换的业务标签做脱敏，保留必要的数值、参数关系和可实施细节。正文联系人字段按授权填写。待确认信息与结论性免责声明放在交付说明，用户模板明确要求的字段按模板处理。

通用模板按 A4 纵向导出，正文宋体约 10.5 磅、行距 1.15，中文标题按层级使用黑体或宋体。指定 Word 模板时保留它的版式。详见 [渲染命令](delivery-contract.md)。

## 申请文件

| 分件 | 内容 |
| --- | --- |
| 权利要求书 | 阿拉伯数字连续编号，每项末尾用句号。独立项记载解决技术问题所需的必要技术特征，按适用规则使用前序及特征部分。从属项依正确的引用关系增加限定。 |
| 说明书 | 发明名称之后，依次写技术领域、背景技术、发明内容、附图说明（有图时）和具体实施方式。发明内容交代问题、方案和有益效果。实施方式说明各关键步骤的对象、操作、目的和效果，给出足以实施的支持。 |
| 说明书摘要 | 一段说明发明名称、技术领域、所解决的问题、方案要点和用途，可写主要技术效果。按当期官方规则核对，通常不超过 300 字。 |
| 说明书附图、摘要附图 | 有图时分为两件。摘要附图从说明书附图中选择代表性的一幅。无附图且符合适用规范时，在清单列为不适用。 |
| 初步查新笔记 | 记录日期、数据库、检索式、最接近文献、差异及检索限制。 |
| 发明专利请求书信息确认表 | 核对申请人、发明人及署名要求、联系人、通信信息、代理、优先权、费减、保密审查、提前公开、附件及签署事项。未知项标记待确认，证件等敏感材料另存。 |
| 提交文件清单 | 列明交付文件、需确认事项、附图适用性和后续官方转换或签章事项。 |

统一名称、术语、符号和标号。技术步骤、设备结构、公式、参数边界和限定语均要有说明书支持。检查从属引用的在先基础，多项从属引用按法定规则处理。避免模糊措辞、宣传语、产品型号和空泛的效果限定，按技术实际决定权项数量及并列客体。说明书使用清楚、规范的术语，避免以权利要求编号代替技术说明。

全套文件使用 [分件目录与验收](delivery-contract.md)。双方上游均提供完整申请结构，分件 Word 及文件编号以 HuangXinzhe 方案为准。无需用同一 Word 或 PDF 合订成默认交付物。
